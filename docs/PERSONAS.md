# 페르소나: 단계별로 이력서를 보는 기준이 어떻게 다른가

## 한 줄 요약
**12개 평가 축은 모든 페르소나가 같고, 다음 다섯 가지가 단계마다 다르다.** 모두 공고 데이터에서 계산한다.
1. 축 가중치
2. 점수별 증거 기준
3. 탈락 요인(경계 신호)
4. 전형 비율
5. 질문 은행

## 1. 무엇이 다른가
| 구성 요소 | 단계별로 어떻게 다른가 | 출처 |
|---|---|---|
| 축 가중치 | 같은 이력서도 단계마다 총점이 다르다. 예: 성장기는 ownership과 ai_leverage, 대기업은 scale_performance와 consistency_reliability를 더 본다 | `[통계]` 공고의 필수(1.0)·업무(0.7)·우대(0.5) 항목을 축별로 집계 |
| lift | 전체 평균 대비 그 단계가 더 보는 축(1.2 이상)과 덜 보는 축(0.8 이하) | `[통계]` |
| 증거 기준 (점수별) | 같은 4점이라도 의미가 다르다. 초기 단계는 "직접 끝까지 만든 범위", 대기업은 "지표와 용량 추정 근거" | 카드 작성 LLM이 해당 단계 공고 인용으로 구체화 → `[통계]` + `[단계추정]` |
| 경계 신호 | 그 단계 공고들이 명시하거나 시사하는 탈락 요인 | `[공고]` 해석에서 원문 인용으로 추출 |
| 전형 | 과제, 코테, 라이브 코딩, AI 면접, 컬처핏 비율 | `[통계]` |
| 질문 은행 | 그 단계 공고의 실제 업무 항목에서 만든 질문과 꼬리질문 | `[공고]` |
| 직무 유형 보정 | product_backend, platform_backend, fullstack, sdet_quality, devops_sre의 lift를 가중치에 곱한다 | `[통계]` |

## 2. 계산 방법 (`crawler/persona_build.py`)
1. **공고 벡터**: 해석된 각 공고의 항목을 축별로 합한다(필수 1.0, 업무 0.7, 우대 0.5). 공고 하나의 합이 1이 되게 정규화한다.
2. **회사 균형**: 회사별로 먼저 평균을 내고, 그다음 회사들 사이에서 평균을 낸다.
   - 공고를 많이 올린 회사 하나가 단계 전체를 대표하는 것을 막는다.
   - 실제로 이걸 적용하기 전에는 후기 단계 40건 중 21건이 당근, 대기업 51건 중 31건이 쿠팡이었다.
3. **축소추정**: `w = n/(n+5)·단계 + 5/(n+5)·전체`. 여기서 n은 회사 수다. 회사가 적은 단계는 전체 평균 쪽으로 당겨진다.
4. **lift** = 단계 가중치 / 전체 가중치.
   - 1.2 이상이면 특징 축, 0.8 이하이면 덜 보는 축으로 표시한다.
5. **신뢰도**: 회사 15개 이상이면 high, 6개 이상이면 medium, 그보다 적으면 low.
   - 회사가 3개 미만인 단계는 카드를 만들지 않고 **전체 시장 기준 대체 카드**를 쓴다.
6. **유사도**: 단계 벡터끼리 코사인 유사도를 잰다. 0.95를 넘으면 병합 후보로 표시한다. 몇 개로 나눌지를 데이터가 판단하게 하는 장치다.

## 3. 카드 작성과 검증 (`crawler/persona_write.py`)
- **입력**: 단계 JSON(가중치, lift, 축별 원문 인용, 경계 신호, 전형, 팀 문제, 업무 항목)과 인접 단계의 lift
- **출력 형식**
  - 요약 한 줄
  - 맥락
  - 축 최대 6개: 기대하는 것, 2~5점 증거 기준, 근거 uid
  - 경계 신호
  - 인접 단계와의 차이
  - 면접 방식
  - 질문 은행
  - 지원자 조언
- **존재 검사**: 인용한 uid가 그 단계의 근거 집합 안에 있는가
- **지지 검사**: 인용한 공고의 해석에 실제로 그 축의 항목이 있는가. 경계 신호와 질문도 같은 방식으로 확인한다.
  - 근거가 모두 탈락한 축은 카드에서 뺀다.
  - 본문 안의 인용구가 원문에 없으면 `[인용 미검증]`으로 표시한다.
- **캐시**: 입력 해시(데이터, 프롬프트, 스키마, 모델, 작성기 버전)가 같으면 LLM을 부르지 않는다.

## 4. 리뷰에서 페르소나가 쓰이는 방식
- **엔진 (`coach/`)**
  - `context_pack`이 대상 단계의 가중치(직무 보정 포함), 상위 축, 증거 기준, 경계 신호, 전형을 담는다.
  - 리뷰 LLM은 상위 축만 0~5점으로 채점한다.
  - 리포트의 **가중 총점**은 그 단계 가중치로 계산한다.
- **에이전트 (`prompts/reviewers/stage-*.md`)**
  - 같은 데이터를 쓴다. 단계 페르소나, HR, 멘토 렌즈가 병렬로 평가하고 review-critic이 검수한다.
- **단계 무관 렌즈**: hr-recruiter, headhunter, culture-peer, domain-fintech-commerce
  - 이 넷은 아직 수작업 정의다. 도메인 렌즈를 데이터 기반으로 바꾸는 작업이 남아 있다.
