# 최종 산출물(피드백 리포트) 형식

- `coach/report.py`가 항상 같은 순서와 형식으로 만든다.
- 그래서 시점별, 지원자별 비교가 가능하고 나중에 서비스 화면으로 그대로 옮길 수 있다.
- 파일은 두 가지를 함께 저장한다.
  - `.md`: 사람이 읽는 리포트
  - `.json`: 기계가 읽는 데이터. meta, fit, weighted_total, result, validation, request를 담는다.

| # | 섹션 | 내용 | 왜 |
|---|---|---|---|
| 0 | 메타 | 대상(익명 가능), 생성 시각, 모델, 비용, 기준 단계와 직무와 공고, **데이터 기준**(현재 모집 중), **품질 지표**(검증 통과율, 날조 의심, 제외된 지적 수), **근거 출처 분포** | 신뢰도를 먼저 보여 준다 |
| 1 | 한눈에 보기 | 핵심 3줄, **가중 총점/100**(그 단계 가중치 기준), 가장 큰 레버 | 30초 안에 결론 |
| 2 | 단계 적합도 | 단계별 적합도, 신뢰도(근거 회사 수), 연차 감점, 핵심 갭 3 (단계를 자동 선택했을 때) | 어디에 지원할지 |
| 3 | 축별 평가 | 가중치 순 표: 축, 가중치, 점수(0~5), 이유 | 무엇이 약한지 구조적으로 |
| 4 | 우선 개선 3가지 | 제목, 왜(근거 태그), 어떻게(어느 bullet을 어떻게) | 실행 우선순위 |
| 5 | 라인별 수정안 | 심각도, 이력서 원문, 문제, **바로 쓸 수 있는 수정안**(모르는 값은 `[측정값]`), [출처유형] 근거 | 바로 적용 |
| 6 | 공고 매칭 | (공고를 지정한 경우) 필수 요건별 충족/부분/미충족, 이력서 근거, **진짜 갭 vs 무시 가능** | 지원 판단 |
| 7 | 예상 면접 질문 | 질문, 꼬리질문, 근거(이력서 문장이나 공고 uid) | 면접 준비 |
| 8 | 한계 | 추정·의견 근거 수, 단계 데이터 신뢰도, 검증에서 제외된 지적, 지표가 예비 단계라는 점 | 과신 방지 |

## 다른 형식이 있으면
- 요청 메시지에 "이 포맷을 참고해서"라는 말이 있었지만 **포맷이 첨부되지 않았습니다.**
- 참고할 포맷을 주시면 이 표와 `coach/report.py`를 그 기준에 맞춰 조정하겠습니다.
- 렌더러는 결과 JSON과 분리되어 있어서 데이터 구조를 바꾸지 않고 형식만 바꿀 수 있습니다.

## 예시
- 가상 인물: `out/test/*-review-early.md`
- 실제 이력서: `profiles/me/reviews/*-review-*.md` (프로필 저장소 안)
