# 최종 산출물(피드백 리포트) 형식

- `coach/report.py`가 항상 같은 순서와 형식으로 만든다.
- 그래서 시점별, 지원자별 비교가 가능하고 나중에 서비스 화면으로 그대로 옮길 수 있다.
- 파일은 두 가지를 함께 저장한다.
  - `.md`: 사람이 읽는 리포트
  - `.json`: 기계가 읽는 데이터. meta, fit, weighted_total, result, validation, request를 담는다.

| # | 섹션 | 내용 | 왜 |
|---|---|---|---|
| 0 | 메타 | 대상(익명 가능), 생성 시각, 모델, 비용, 기준 단계와 직무와 공고, **데이터 기준**(현재 모집 중), **품질 지표**(검증 통과율, 날조 의심, 제외된 지적 수), **근거 출처 분포** | 신뢰도를 먼저 보여 준다 |
| 1 | 한눈에 보기 | 핵심 3줄, **가중 총점/100**(그 단계 가중치 기준), 가장 큰 레버 | 30초 안에 결론 |
| 2 | 단계 적합도 | 단계별 적합도, 신뢰도(근거 회사 수), 연차 감점, 핵심 갭 3 (단계를 자동 선택했을 때) | 어디에 지원할지 |
| 3 | 축별 평가 | 가중치 순 표: 축, 가중치, 점수(0~5), 이유 | 무엇이 약한지 구조적으로 |
| 4 | 우선 개선 3가지 | 제목, 왜(근거 태그), 어떻게(어느 bullet을 어떻게) | 실행 우선순위 |
| 5 | 라인별 수정안 | 심각도, 이력서 원문, 문제, **바로 쓸 수 있는 수정안**(모르는 값은 `[측정값]`), [출처유형] 근거 | 바로 적용 |
| 6 | 공고 매칭 | (공고를 지정한 경우) 필수 요건별 충족/부분/미충족, 이력서 근거, **진짜 갭 vs 무시 가능** | 지원 판단 |
| 7 | 예상 면접 질문 | 질문, 꼬리질문, 근거(이력서 문장이나 공고 uid) | 면접 준비 |
| 8 | 한계 | 추정·의견 근거 수, 단계 데이터 신뢰도, 검증에서 제외된 지적, 지표가 예비 단계라는 점 | 과신 방지 |

## 패널 리포트 (`coach.cli panel`, `coach/panel.py`)
- 외부 자료 `recruiter-review-v1`(채용담당자 패널 형식)을 참고해 추가한 두 번째 산출물이다.
- 단계 페르소나 5명(근거 3개사 이상인 단계)이 **각자 독립적으로** 판정한다. **평균은 내지 않는다.**
- 파일: `<날짜>-panel.md`, `<날짜>-panel.json`(meta, panel, aggregate)

| # | 섹션 | 내용 | 왜 |
|---|---|---|---|
| ① | 판정 보드 | 페르소나별 PASS/HOLD/REJECT, 상위 5축 점수와 그 축 가중치(w%) | 평균이 가리는 의견 갈림을 보여 준다 |
| ② | 시장 적합도 | 판정별 "자리" 수(그 페르소나가 대표하는 모집 중 공고 수), **스택 위치**(Node/TS 필수·우대·다른 스택 필수·무관)별 분포 | "몇 개 공고에서 막히는가" |
| ③ | 합의된 킬 포인트 | 탈락 사유 축별 **독립 표** 수. 2표 이상이거나 '승격'(절반 이상이 2점 이하)이면 대응, 아니면 "대응하지 마세요" | 한 명의 취향에 휘둘리지 않게 |
| ④ | 면접 예상 질문 | 주제별로 묶고 여러 페르소나가 겹쳐 물은 주제를 위로 | 준비 우선순위 |
| ⑤ | 고칠 것 | 같은 문장(before)을 지목한 독립 표 순. before는 이력서 원문 그대로, after의 모르는 수치는 `[측정값]`. 이전 판과 같은 문장을 다시 지목하면 경고 | 가장 구체적인 합의 |
| ⑥ | 첫 10초 인상 | 페르소나별 첫인상 | 서류 스크리닝 시뮬레이션 |
| — | 감안할 것 | 얇은 표본(N≤12), 데이터 기준, 일반화 한계 | 과신 방지 |

- **독립 표**: 가중치 벡터에서 패널 평균을 뺀 '차이 벡터'의 코사인이 0.8을 넘는 페르소나는 1표로 센다.
  - 원래 가중치로 비교하면 공통 축 때문에 모두 0.93~0.98로 나와 전부 한 표로 묶이는 문제가 있었다(2026-10-26 수정).
- **반환값 검사**: kill_quote와 before가 이력서에 실제로 있는지, after가 비어 있지 않은지, 이력서에 없는 단위 수치를 만들지 않았는지 확인한다. 실패하면 1회 재시도한다.
- 지원자의 연차·스택은 **이력서에서만** 읽는다. 공고 모집단의 연차를 지원자 것으로 착각하지 않게 하려는 규칙이다.

## 예시

- 실제 이력서: `profiles/me/reviews/*-review-*.md` (프로필 저장소 안)
